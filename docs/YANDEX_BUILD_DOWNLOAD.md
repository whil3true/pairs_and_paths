# Как скачать готовый ZIP Cozy Gallery для Яндекс Игр

## Скачивание и загрузка

1. Войдите в GitHub и откройте [Actions → CI](https://github.com/whil3true/pairs_and_paths/actions/workflows/ci.yml).
2. После merge выберите последний **успешный запуск `push` для ветки `dev`**. Сверьте дату и SHA коммита с актуальным `dev`: старый зелёный запуск не подтверждает новую версию. До merge выберите успешный запуск **`pull_request` вашего Draft PR** из `feature/yandex-release-zip` в `dev`; Draft PR тоже получает готовый архив. Обычный `push` feature-ветки выполняет проверки, но релизный job пропускается.
3. Откройте Summary запуска. В разделе **Artifacts** нажмите **`cozy-gallery-yandex`**. Прямая ссылка также есть в Summary задания **Yandex upload-ready ZIP** (`yandex-release`). Само задание тоже должно завершиться успешно.
4. GitHub скачает **`cozy-gallery-yandex.zip`**. Это готовый архив для Яндекс Игр: загружайте его целиком, без распаковки, редактирования или повторной упаковки.
5. При желании откройте ZIP в архиваторе только для просмотра. В корне должны быть `index.html`, `styles.css`, `js/`, `vendor/` и `assets/`. Внутри не должно быть внешней папки `dist/` или другого ZIP. Среди файлов должны быть `js/main.js`, `vendor/phaser.js`, `vendor/phaser.LICENSE.txt`, 100 картин в `assets/artwork/pipeline/full/` и 100 миниатюр в `assets/artwork/pipeline/thumbs/`. CI уже проверяет структуру и содержимое; просмотр не является обязательной операцией.
6. Откройте [консоль разработчика Яндекс Игр](https://games.yandex.ru/console/) → нужную игру → **Черновик → Общее → Архив** и загрузите **скачанный ZIP целиком**. Дождитесь обработки и проверьте игру в черновике, включая настоящий SDK и рекламу. CI не загружает игру в Яндекс и не отправляет её на модерацию.

## Какой артефакт выбирать

| Название | Назначение |
| --- | --- |
| **`cozy-gallery-yandex`** | Готовый релизный ZIP для загрузки в Яндекс Игры; выбирать его |
| `production-dist` | Промежуточная передача проверенной сборки между заданиями CI |
| `github-pages` в workflow Deploy GitHub Pages | Служебный артефакт публикации Pages; для Яндекса не использовать |

Не скачивайте все артефакты одним архивом: GitHub может добавить внешние папки. Нажимайте непосредственно **`cozy-gallery-yandex`**.

## Что проверяет CI

Существующий `validate` сохраняет TypeScript typecheck, unit-тесты, симуляцию 10 000 полей, симуляцию препятствий, production build, проверку ассетов и размера. `scripts/build.mjs` по-прежнему использует `tsc`, копирует статические файлы и локальный Phaser; новый bundler не используется. Из production исключены только исходные заметки `assets/audio/README.md`. Лицензии шрифтов сохранены, полная MIT-лицензия Phaser копируется из установленной зависимости в `vendor/phaser.LICENSE.txt`.

`check-assets.mjs` проверяет развёрнутые runtime-каталоги, включая все 100 картин и миниатюры, 30 символов, 10 баннеров, UI, логотипы, шрифты и аудио. SHA-256 каждого утверждённого ассета сравнивается со снимком `docs/audit/production-assets.sha256.json`, а deployed-файлы — с `public/`. Изображения не перекодируются и не исключаются ради размера.

Новый валидатор `scripts/check-yandex-build.py` (Python 3, только стандартная библиотека) проверяет папку и ZIP:

- Единственный `index.html` в корне, загрузку CSS, Phaser и `js/main.js`.
- Локальные ссылки HTML/CSS, статические и строковые динамические импорты нативных ES-модулей, литералы ресурсов и `new URL`.
- Полный утверждённый каталог и SHA-256 ассетов; точный состав production-файлов.
- Лимит **100 000 000 байт распакованного содержимого**, CRC/чтение каждого ZIP-файла.
- Отсутствие `dist/`-обёртки, вложенных архивов, исходников, source maps, тестов, документов разработки, конфигов, скрытых файлов, симлинков, повторяющихся записей, коллизий регистра, опасных путей, пробелов и не-ASCII имён.
- Официальный путь `/sdk.js` в compiled-коде и отсутствие локального `sdk.js`: его предоставляет хостинг Яндекса.

После успешного `validate` отдельный `yandex-release` получает **эту же** сборку через `production-dist`, без повторной компиляции. `upload-artifact@v4` упаковывает непосредственно содержимое `dist/`. Затем CI скачивает **фактический ZIP этого артефакта через GitHub API**, повторяет проверки и сравнивает все пути и каждый байт с проверенным `dist/`. Summary и логи содержат размер ZIP, распакованный размер, число файлов и SHA-256. Отчёты остаются вне production-папки.

Регулярные выражения проверяют используемые в проекте формы импортов и ссылок; динамически собираемые каталожные пути покрываются существующей проверкой каталогов и снимком ассетов. Проверка архива не заменяет запуск настоящей игры в черновике.

Локальная проверка после `npm run build`:

```sh
python3 -m unittest discover -s scripts -p test_check_yandex_build.py -v
python3 scripts/check-yandex-build.py dist
python3 scripts/check-yandex-build.py /path/to/cozy-gallery-yandex.zip --compare dist
```

Выполняйте команды из checkout той же версии: валидатор использует repository snapshot и список исходных модулей, не добавляя их в ZIP.

## Неуспешный CI или отсутствующий архив

Откройте красное задание и первый упавший шаг. Исправьте причину и дождитесь полностью успешного запуска. Если публикация уже прошла, а скачивание/проверка ZIP затем упали, артефакт может быть виден, но **использовать его нельзя до успешной проверки**. При временном сбое GitHub можно выбрать **Re-run failed jobs**; при изменении исходников нужен новый запуск.

Если артефакт истёк, выберите **Run workflow → dev** в CI либо повторите запуск актуального PR. Не создавайте ради скачивания новый tag или GitHub Release. Для чужого fork PR политика GitHub может потребовать разрешения владельца на запуск; обычный Draft PR в этом репозитории работает без такого шага.

## GitHub Pages

[Текущая standalone-версия](https://whil3true.github.io/pairs_and_paths/) продолжает публиковаться из `dev` отдельным workflow `pages.yml`. Его настройки, адрес и игровой/SDK-код не меняются. До merge этот PR ничего не публикует на Pages. Статус Pages смотрите отдельно в [Deploy GitHub Pages](https://github.com/whil3true/pairs_and_paths/actions/workflows/pages.yml).

Официальные источники: [требования к загрузке игры](https://yandex.ru/dev/games/doc/ru/console/add-new-game), [upload-artifact v4](https://github.com/actions/upload-artifact/tree/v4). Готовый ZIP подтверждает упаковку; модерация и проверка поведения игры выполняются отдельно в черновике Яндекса.
